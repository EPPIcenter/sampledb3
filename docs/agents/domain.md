# Domain docs

- **Naming a domain concept**: read `CONTEXT.md`, the glossary of entity names, hierarchies, and scope.
- **Changing an area a design decision covers**: read the ADRs in `docs/adr/` that touch it.
- **Describing a user-facing workflow**: read the user guide in `packages/docs/`.

`CODING_STANDARDS.md` has the rules for using the glossary's terms and for contradicting an ADR.
